项目一｜擎舵 3.0：营销创意 Agent 生产质量升级

项目定位：百度营销体系下的 AI 创意生产平台，承接广告图、营销视频、口播素材和批量投放物料生产。

用户对象：广告主、代理商、运营团队、文创广告物料设计团队。

原问题：2.0 是工具集合，用户需要自己找工具、填参数、判断结果、寻找续改入口。它能承载生成能力，但不天然承接营销任务。

我的角色：主导图片 Agent 2.0 整体体验方案，负责 3.0 首页、超级输入框、导航、AI 创编大师 Workflow 及复杂状态原型验证。正确边界是“主导体验方案并协同产研落地”，不写成“训练模型”或“独立开发正式产品”。

核心设计判断：从工具集合到 Agent 生产系统，让广告素材从“能生成”走向“可交付”。

擎舵 3.0｜平台搭建：从找工具到表达任务

首页升级：创作启动页

  • 问题：用户不知道先用哪个工具开始。
  • 判断：首页需要从工具货架切到创作启动台。
  • 我的动作：超级输入框、智能标签、灵感案例、高频入口、任务启动。
  • 验证口径：创作启动率、首次任务启动耗时、首页到生成路径步数。
  • 结论：首页解决的是“如何开始生产”。

导航与空间升级：极窄侧导释放创作区

  • 问题：工具入口多，创作空间被挤压。
  • 判断：平台重心要回到创作任务本身。
  • 我的动作：低频入口收敛到极窄侧导，创作区承接输入、生成结果和后续动作。
  • 验证口径：工具跳转次数、任务连续率、创作区使用率。
  • 结论：空间结构要服务持续创作，避免把首屏变成工具陈列。

任务页升级：生成结果页变成续改枢纽

  • 问题：生成结果出来后，用户不知道下一步怎么改。
  • 判断：结果页要接住生成后的续改和复用。
  • 我的动作：再生成、去编辑器、智能扩图、智能抠图、图转视频、保存资产、复用已有素材。
  • 验证口径：结果续改率、保存率、资产复用率。
  • 结论：把“不满意”从终止点，转化为下一步生产动作。

擎舵 3.0｜转场：平台解决启动，质量决定交付

平台框架解决的是用户如何开始和如何连续创作；进入真实广告投放场景后，更关键的问题是生成结果是否可用。运营测试显示，图片 Agent 提质前初始可用率只有 38%，因此第二阶段进入生产质量提质。

阶段一平台搭建

解决怎么开始、怎么连续创作。设计动作：首页 / 超级输入框 / 极窄侧导 / 任务页。

阶段二质量提质

解决结果能否投放、能否修改、能否复用。设计动作：六类质量约束 / Skill 工作流 / 输出校验 / 结果续改。

擎舵 3.0｜LUI + GUI + Workflow：为什么纯聊天框不够

纯 LUI 可以降低启动门槛，但无法承接营销创作中的结构化编辑、结果预览、分镜控制和资产复用；纯 GUI 可控但启动成本高。因此我采用 LUI + GUI + Workflow 的混合方式。

  • LUI：目标表达、意图解析、需求澄清、阶段推进。
  • GUI：结构化编辑、结果预览、局部修改、保存复用。
  • Workflow：任务拆解、状态记录、上下文保留、回退续改。

巧匠｜设计参与训练质量

样本准备：训练质量从样本开始

问题：设计师不知道什么样的图片适合训练，样本质量会影响训练结果。

我的动作：样本数量提示、清晰度提示、风格一致性提示、主体一致提示、低质 / 水印 / 文字干扰提醒、训练前检查、样本状态分类。

结论：我把算法隐性的样本要求，整理成设计师可理解的训练前检查规则。

训练过程：让等待过程变成可理解的任务状态

我的动作：上传样本、配置参数、提交训练、排队中、训练中、训练完成、训练失败、失败原因、测试生成入口、发布共享。

结论：我把模型训练从黑盒过程，整理成可理解、可追踪、可继续操作的任务流。

模型资产：训练完成后，还要进入团队资产

我的动作：模型卡片、基础模型、触发词、示例图、风格标签、行业标签、适用场景、团队共享、优质案例关联。

结论：让个人训练经验沉淀为团队可复用的生产能力。

巧匠｜生图调用与质量评估

生图调用：在文生图 / 批量生图中选择模型，设置 Prompt、强度、尺寸和批量生成参数，支持历史模型复用，让结果进入评估与沉淀。

质量评估维度：图片质量、真实性、主体元素、Prompt 控制力、风格一致性、广告可用性、复用价值、用户满意度。

边界说明：质量提升由模型能力、样本质量、运营策略和产品体验共同影响；我的设计价值在于建立训练、调用、评估与复用闭环，让质量问题能被发现、反馈和优化。
